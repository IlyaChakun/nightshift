# Plan item or status page

A plan item says what to do, why, and how to check it is done. A status page says what holds now and what comes next.

Budget: plan item 200 words typical, 800 max; status page 300 typical, 600 max (our numbers, chosen so a handoff stays cheap to load).

## Plan item

1. Title: the change as a commit subject (`feat(x): ...`).
2. Source: the request, design section or finding it comes from.
3. What to do, in a few lines.
4. How to check: the test or command that proves it.

## Status page

- Last done, next step, open questions. Rewrite it; never append history.
- A fact that holds only for one phase lives in that phase's file.

# Short title of the feature

## Problem

Who has the problem, what happens today, and what it costs. Two or three sentences, with the evidence (a link to the ticket, the book or a metric).

## Goals

- The outcome a person can observe, with the metric that shows it and its target.

## Non-goals

- What this work does not do, so the scope stays small.

## Solution

The chosen approach in a few lines. Add a mermaid diagram when the flow or the architecture changes.

## Risks

- What could go wrong, how likely, and how we would notice.

## Acceptance Criteria

- Given a starting state, when an action happens, then the observable result.
- Given an error state, when the action happens, then the visible failure and how it is recovered.

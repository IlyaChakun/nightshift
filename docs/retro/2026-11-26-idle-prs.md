# Why pull requests sat open for hours (2026-11-26)

## What happened

At 10:06 UTC nine PRs were open. Seven were minutes old and in flight. Two were not: #253 (draft, 13 hours, conflicts with `main`) and #272 (1h45, conflicts with `main`, no checks at all). Earlier the same day #219 sat with no checks for the same reason, and #278 and #298 did too. Each time the author thread had ended, or was waiting for a CI that could not start.

## Causes (ordered by how much time each cost)

1. **A PR that conflicts with `main` gets no CI.** GitHub does not build a conflicting head, so the check list stays empty. "Poll the checks and merge on green" then waits forever, and nothing says that an empty list is a failure. Checked: `get_check_runs` of #219 and #272 returned `total_count: 0`.
2. **Parallel threads edit the same shared files.** `docs/status.md`, `docs/decisions.md`, `docs/plan.md`, `docs/design.html` (section hashes and `PLAN`), `AGENTS.md` and the ADR numbers are touched by almost every PR, with up to three build threads at once. The first PR to merge turns the others conflicting. Checked: the conflicts in #219 (twice), #253 and #272 were in exactly these files, and two ADR numbers were taken twice.
3. **A thread ended while its PR was open.** The rule said "do not end a turn to wait for CI" but not "do not end the thread while a PR is open", and a thread with no wake-up has nobody to rebase it. #253 stayed a draft because one self-audit item was unverified, and no rule said who decides.
4. **No sweep.** Nothing lists open PRs by age. The owner found them by looking.
5. **Waiting for the owner is invisible.** PRs that need the owner's button (for example #220) look the same as abandoned ones.

## Fixes

Our workflow (this PR):
- `AGENTS.md` and skill `finish-task` ("Open PRs"): merge `origin/main` before opening and whenever `main` moves, never end a thread with its PR open, list and finish idle PRs at the start of every session, and resolve the shared-file conflicts by keeping both sides.

The factory (planned, not built; the plan item is added after #272 lands): its PRs go through push, PR and merge in code, and the merge train already rebases on a fresh `main` and sends a task back on conflict (`internal/train`), so the factory avoids causes 1 and 2 at merge time. What it lacks is cause 4: a task whose PR has had no event for N hours. The check goes into the conductor: rebase when behind, and list the rest, with what they wait for, in the morning digest. Role prompts need no change: Builder never opens or merges a PR.

## Chat skills (the owner saves these; the synced copies are read-only)

- `autonomous-merge-gate`: add the step "an empty or missing check list means the PR conflicts or CI did not start: merge `origin/main` into the branch, push, and look again. Never wait on an empty list." Add: "a PR that waits for the owner is labelled and listed, not left silent."
- `verify-before-done`: add the check "no PR opened by this thread is still open: each is merged or closed with a reason, or named as waiting for the owner."
- `task-kit`: when a request asks for a change to the repository, state in the restatement that the thread ends with a merged or closed PR.

# Worker cannot reach the book or trusted Git

- What. [A7](../plan/architecture/README.md) adds static negative tests: the Postgres server shares no network with the worker and the worker holds no Postgres credential (`deploy/compose_test.go`, `TestWorkerCannotReachTheBook`), and no package the worker roots reach calls the raw Git runner of `gitops` (`internal/testing/archtest/trusted_test.go`). Neither proves what a running container can do.
- Run. On the stable instance: `docker compose exec worker sh -c 'getent hosts postgres; nc -zw3 postgres 5432; echo rc=$?'`, `docker compose exec worker ls /run/secrets /run/worker-secrets`, and a push to the code host from a scratch repository as the agent: `docker compose exec -u 20001 worker sh -c 'cd /tmp && git init -q x && cd x && git -c user.name=t -c user.email=t@example.test commit -q --allow-empty -m t && git push https://github.com/<owner>/<repo>.git HEAD:refs/heads/ns/escape-test'` (the mirrors under `/repos/<owner>` are mode 0750 for uid 10001, so a push from there fails before it tests anything). Keep the output under `~/nightshift-evals/`.
- Expect. The name `postgres` does not resolve and the connection fails; no `pg_*`, `github_*` or chat secret is listed; the push fails at the egress proxy (`CONNECT` refused with 407) or with an authentication error, never with a local permission error, which would prove nothing.

Status: passed 2026-11-28 on a4dc6b8: `postgres` does not resolve; uid 20001 cannot open `worker_token` or `harness`; the scratch push was refused by egress with `CONNECT` 407.
